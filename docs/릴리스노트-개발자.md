# Gatsby → Next.js 마이그레이션 — 개발자용 변경 노트

> 브랜치: `feat/migrateNextJs` → `develop`
> 한 줄 요약: Gatsby 사이트를 **Next.js(Pages Router) 정적 export**로 전면 이전하고, i18n·데이터·이미지 파이프라인을 재구성하면서 hydration·이미지·레이아웃 버그를 정리했습니다.

---

## 1. 프레임워크 / 렌더링

- **Gatsby → Next.js (Pages Router)**, `next.config.js`에 `output: 'export'`로 **완전 정적 export**.
- styled-components **SSR 셸** 구성(`_document` / `_app`), `#__next` 셀렉터 정렬, 폰트를 `public/`로 이동.
- **hydration 안전성 강화**: 렌더 시점에 `window`를 직접 읽던 코드 제거(LottieWrapper, work 해시 등). 클라이언트 전용 값은 `useRouter().query` / `useEffect`에서만 접근.
- `useResize`를 SSR-safe하게 수정(초기값 false → 마운트 후 측정).

## 2. 국제화 (i18n)

- `gatsby-plugin-intl` → **`next-intl`**.
- `[locale]` 동적 라우팅(`/ko`, `/en`) + 루트 `/` → `/ko` 리다이렉트.
- `getMessages`, `getStaticProps` 헬퍼(`localePaths`/`localeProps`, `fallback: false`).
- **`withTranslations` HOC**로 기존 `injectIntl` 패턴 호환, `formatMessage` values 전달.
- GNB / Layout / Footer / introduce / contact / 홈 섹션을 next-intl + `next/link`로 전환.

## 3. 데이터 레이어

- 런타임 Firestore 호출 → **빌드 타임 client-SDK 데이터 생성**(`buildData` / `buildMembers`)로 SSG에 적합하게 변경.
- 이미지 원격 참조는 `RemoteImage`/`AppImage`로 스왑.

## 4. 검색 (news)

- **Algolia(외부 SaaS) 제거 → `fuse.js` 클라이언트 사이드 검색**.
- 전체 news 인덱스를 `getStaticProps`로 빌드 타임에 동봉, 탭 필터 + 텍스트 검색 + 페이지네이션을 브라우저에서 수행.
- 검색 설정: `keys: ['title','summary','content']`, `threshold: 0.4`, `ignoreLocation: true`.
- `.env`에서 Algolia 키 제거, 의존성·lockfile 정리(약 -445 라인).

## 5. 이미지 파이프라인

- `GatsbyImage` → **`AppImage`**(= `next-image-export-optimizer` 래퍼, `placeholder="blur"`).
- 빌드 타임 **WebP + blur** 생성(`public/images` 대상).
- `probe-image-size`로 실제 intrinsic 치수를 복원해 **next/image 왜곡 방지**, DetailPage 배너 사이징 수정.
- members `bgImage`를 Firebase Storage가 아닌 **로컬 에셋**에서 해석.

### FirstSection(메인 히어로) 최적화

- intro 에셋 전면 WebP화: PNG×8 → 정적 WebP, GIF×2 → **애니메이션 WebP**(`<img>`·애니메이션 유지). **약 25.5MB → 1.8MB**.
- crossfade 두 레이어를 항상 `position:absolute`로 겹쳐 **opacity만 전환** → `static↔absolute` 스왑이 만들던 **전환 시 세로 점프 제거**(layout-shift 0 실측).
- intro 상태를 첫 렌더부터 실제 `src`로 시드 + `object-fit:cover`로 박스 예약 → **초기 CLS 0.74 → 0**.
- 부수 정리: `clearTimeout` on unmount, `useEffect` deps 정정, 미사용 styled prop·중복 래퍼 제거, `alt` 추가, `FrirstWrapper` 오타 수정.

## 6. 정책 페이지

- 정책 문서를 **마크다운**으로: `gray-matter` + `react-markdown` + `rehype-raw`, 라우트 `[locale]/policy/[slug]`.

## 7. 배포 / CI / 툴링

- **Firebase Hosting 정적 export** 설정: `public: out`, SPA·news-function rewrite 제거, `/` → `/ko` 리다이렉트, `_next/static` 캐시 헤더.
- `next-sitemap` 도입.
- 패키지 매니저 **yarn → pnpm**(`node-linker=hoisted`), 환경변수 `NEXT_PUBLIC_*`로 통일, `firebase-key.json` 추적 해제.
- functions: **Node 20 + firebase-functions v6(v1 API) + admin v12**, algolia 자격증명 env화.
- CI: `checkout@v4`, 웹훅 워크플로우 중복 제거, Next 빌드·최적화 이미지 캐시. 빌드/lint 분리.

## 8. 환경변수 / GitHub 시크릿 정리

Algolia 제거와 functions 정리에 따라 더 이상 쓰지 않는 값들이 생겼습니다.

**🗑️ 삭제 OK (이제 아무 데서도 사용 안 함)**

| 시크릿 | 비고 |
|---|---|
| `GATSBY_ALGOLIA_ID` | Algolia → Fuse.js 전환으로 불필요 |
| `GATSBY_ALGOLIA_SEARCH_KEY` | 동상 |
| `GATSBY_ALGOLIA_INDEX_NAME` | 동상 |

**⚠️ 유지 (워크플로가 빌드/배포에 여전히 사용)**

| 시크릿 | 용도 |
|---|---|
| `GATSBY_FIREBASE_*` 7개<br/>(API_KEY / AUTH_DOMAIN / PROJECT_ID / STORAGE_BUCKET / MESSAGING_SENDER_ID / APP_ID / MEASUREMENT_ID) | `.env`에서 `NEXT_PUBLIC_*`로 매핑 |
| `FIREBASE_SERVICE_ACCOUNT_NAMSAN_801DE` | 호스팅 배포 인증 |
| `GITHUB_TOKEN` | GitHub가 자동 제공 — 신경 쓸 필요 없음 |

**곁다리 정리(선택)**

- **Algolia ADMIN 키**: GitHub가 아니라 Firebase Functions 런타임 config(`firebase functions:config:get algolia`)에 있었음. functions를 지웠으니 죽은 값 → 깔끔히 하려면 `firebase functions:config:unset algolia`.
- **Algolia 과금 중단**: 더 안 쓰면 Algolia 대시보드에서 해당 앱/인덱스(`dev_namsan`) 삭제 시 청구 정지.
- **배포된 옛 functions 제거**(코드는 이미 삭제됨):
  `firebase functions:delete helloWorld collectionOnCreate collectionOnUpdate collectionOnDelete --region asia-northeast2`
  또는 functions 없는 상태로 한 번 배포하면 Firebase가 삭제를 제안.

> GitHub 시크릿 삭제는 레포 설정이라 수동 처리 필요. `gh CLI` 인증 시:
> `gh secret delete GATSBY_ALGOLIA_ID` / `GATSBY_ALGOLIA_SEARCH_KEY` / `GATSBY_ALGOLIA_INDEX_NAME`
> (또는 GitHub UI: Settings → Secrets and variables → Actions)

## 9. 라우팅 / URL 변화 (주의)

- 모든 페이지가 **로케일 프리픽스** 구조로: `/work` → `/ko/work`, `/en/work` 등.
- `trailingSlash: true` (정적 export): 정규 경로는 끝에 `/` 포함(`/ko/`).
